    39→    39→## Step 2: DESIGN - Palette & Font Plan
    40→    40→
    41→    41→**Before writing any ReportLab code, you MUST generate the color palette via the `palette.generate` command.** This is not optional. Do NOT hardcode hex colors. Do NOT pick colors by feel.
    42→    42→
    43→    43→### 2a. Generate Palette (MANDATORY)
    44→    44→
    45→    45→**Run this command FIRST. Copy-paste its output directly into your Python script:**
    46→    46→
    47→    47→```bash
    48→    48→python3 "$PDF_SKILL_DIR/scripts/pdf.py" palette.generate --title "<document title>" --mode minimal
    49→    49→```
    50→    50→
    51→    51→The command auto-derives the design intent from the document title, computes a mathematically harmonious palette, and outputs ready-to-paste ReportLab Python code:
    52→    52→
    53→    53→```python
    54→    54→# ━━ Color Palette (auto-generated by pdf.py palette.generate) ━━
    55→    55→# Intent: neutral | Mode: minimal | Harmony: split_complementary
    56→    56→# Contrast: text:bg=14.12 | accent:bg=3.06
    57→    57→from reportlab.lib import colors
    58→    58→ACCENT       = colors.HexColor('#2f97b9')
    59→    59→TEXT_PRIMARY  = colors.HexColor('#252422')
    60→    60→TEXT_MUTED    = colors.HexColor('#8d8981')
    61→    61→BG_SURFACE    = colors.HexColor('#dfdad2')
    62→    62→BG_PAGE       = colors.HexColor('#f5f4f3')
    63→    63→SURFACE_RGBA  = 'rgba(0,0,0,0.03)'
    64→    64→
    65→    65→# ReportLab table colors
    66→    66→TABLE_HEADER_COLOR = ACCENT
    67→    67→TABLE_HEADER_TEXT  = colors.white
    68→    68→TABLE_ROW_EVEN     = colors.white
    69→    69→TABLE_ROW_ODD      = BG_SURFACE
    70→    70→```
    71→    71→
    72→    72→**Options:**
    73→    73→- `--mode minimal` (default, recommended for 50%+ of documents) | `dark` | `pastel` | `jewel` | `light`
    74→    74→- `--harmony auto` (default, recommended) | `complementary` | `split_complementary` | `analogous` | `triadic` | `monochrome`
    75→    75→- `--format python` (default) | `json` | `css`
    76→    76→- `--seed <int>` - for reproducible palettes across regenerations
    77→    77→
    78→    78→**⚠️ FORBIDDEN:**
    79→    79→- ❌ Writing `colors.HexColor('#xxxxxx')` with any hex value you chose yourself
    80→    80→- ❌ Using `colors.red`, `colors.blue`, or any ReportLab named color for design elements
    81→    81→- ❌ Skipping this step and picking colors "that look good"
    82→    82→- ❌ Using different palettes for different sections of the same document
    83→    83→
    84→    84→**✅ The ONLY acceptable way to get colors:** Run `palette.generate`, copy the output.

   109→   109→## Step 3: EDIT - Content Transformation
   110→   110→
   111→   111→**Before writing any code, restructure raw text into visual roles.** This is the most impactful quality step - skipping it produces "Word document with a PDF extension".
   112→   112→
   113→   113→### 3a. Typographic Role Extraction
   114→   114→
   115→   115→Parse raw text and categorize content into visual roles:
   116→   116→
   117→   117→| Role | ReportLab Mapping | Description |
   118→   118→|------|------------------|-------------|
   119→   119→| **Hero / Display** | Cover title (36-42pt) or section opener | 1-5 words, the emotional hook |
   120→   120→| **Kicker / Eyebrow** | Subtitle or section intro (10-12pt, muted) | Tiny context line above main heading |
   121→   121→| **Data Sculpture** | CalloutBox or bold stat block | Extract impactful numbers (97%, $4.2M, -45ms) |
   122→   122→| **Pull Quote** | BlockQuote (italic + left indent 24pt + accent border) | Most provocative sentence, standalone |
   123→   123→| **Body** | Standard paragraph | Everything else |
   124→   124→
   125→   125→**Rule**: Before writing any body paragraph, scan for numbers with units. Every metric like "revenue grew by 12%" or "latency dropped to 45ms" MUST be extracted into a CalloutBox or metrics table - never buried in paragraph prose. See §Data-to-Ink Ratio Rules below.
   126→   126→
   127→   127→### 3b. Section Pacing
   128→   128→
   129→   129→- If any H1 section has **>400 words** of continuous body text without visual breaks, split into H2 subsections or insert a visual break (table, chart, callout)
   130→   130→- Aim for at least 1 visual element (table/chart/callout) per 2-3 pages of body text
   131→   131→- Dense text walls are the #1 sign of poor report design

   137→   137→## Character Safety Rule (MANDATORY)
   138→   138→
   139→   139→Three rules for safe character handling in ReportLab PDFs:
   140→   140→
   141→   141→**a) Superscripts and subscripts**: Use `<super>`/`<sub>` tags, never raw Unicode superscript/subscript characters (e.g., `\u00b2`, `\u2082`).
   142→   142→
   143→   143→**b) Emoji**: ReportLab cannot render emoji. If content contains emoji, use Creative brief (HTML + Playwright).
   144→   144→
   145→   145→**c) Font fallback for mixed CJK/Latin text**: After registering fonts, call `install_font_fallback()` once. This automatically wraps missing-glyph characters in `<font>` tags inside every `Paragraph()`. No manual `<font name="...">` wrapping needed for mixed Chinese-English text.
   146→   146→
   147→   147→Mathematical/relational operators (×, ÷, ±, ≤, √, ∑, ≅, ∫, π, ∠, Δ, etc.) are safe to use as literal characters in `Paragraph()` - both SimHei and Times New Roman have these glyphs.
   148→   148→
   149→   149→| Need | Correct Method | Correct Example |
   150→   150→|------|---------------|---------|
   151→   151→| Superscript | `<super>` tag in `Paragraph()` | `Paragraph('10<super>2</super> × 10<super>3</super> = 10<super>5</super>', style)` |
   152→   152→| Subscript | `<sub>` tag in `Paragraph()` | `Paragraph('H<sub>2</sub>O', style)` |
   153→   153→| Bold | `<b>` tag in `Paragraph()` | `Paragraph('<b>Title</b>', style)` |
   154→   154→| Math operators | Literal char in `Paragraph()` | `Paragraph('AB ⊥ AC, ∠A = 90°, and ΔABC ≅ ΔDCF', style)` |
   155→   155→| Scientific notation | Combined tags in `Paragraph()` | `Paragraph('1.2 × 10<super>8</super> kg/m<super>3</super>', style)` |
   156→   156→
   157→   157→```python
   158→   158→from reportlab.platypus import Paragraph
   159→   159→from reportlab.lib.styles import ParagraphStyle
   160→   160→from reportlab.lib.enums import TA_LEFT, TA_CENTER, TA_JUSTIFY
   161→   161→
   162→   162→body_style = ParagraphStyle(
   163→   163→    name="ENBodyStyle",
   164→   164→    fontName="Times New Roman",
   165→   165→    fontSize=10.5,
   166→   166→    leading=18,
   167→   167→    alignment=TA_JUSTIFY,
   168→   168→)
   169→   169→
   170→   170→# Superscript: area unit
   171→   171→Paragraph('Total area: 500 m<super>2</super>', body_style)
   172→   172→
   173→   173→# Subscript: chemical formula
   174→   174→Paragraph('The reaction produces CO<sub>2</sub> and H<sub>2</sub>O', body_style)
   175→   175→
   176→   176→# Scientific notation
   177→   177→Paragraph('Speed of light: 3.0 × 10<super>8</super> m/s', body_style)
   178→   178→
   179→   179→# Combined
   180→   180→Paragraph('E<sub>k</sub> = mv<super>2</super>/2', body_style)
   181→   181→
   182→   182→# Bold heading
   183→   183→Paragraph('<b>Chapter 1: Introduction</b>', header_style)
   184→   184→
   185→   185→# Math symbols
   186→   186→Paragraph('When ∠ A = 90°, AB ⊥ AC and ΔABC ≅ ΔDEF', body_style)
   187→   187→```
   188→   188→
   189→   189→**Pre-generation check - before writing ANY string, ask:**
   190→   190→> "Does this string contain a character outside basic CJK or Mathematical/relational operators?"
   191→   191→> If YES → it MUST be inside a `Paragraph()` with the appropriate tag.
   192→   192→> If it is a superscript/subscript digit in raw unicode escape form → REPLACE with `<super>`/`<sub>` tag.
   193→   193→
   194→   194→**NEVER rely on post-generation scanning. Prevent at the point of writing.**
   195→   195→
   196→   196→**Encoding safety - before writing ANY content text:**
   197→   197→> "Does this string contain Japanese kana (の, が, は etc.) or rare Unicode symbols?"
   198→   198→> If YES → REPLACE with safe plain Chinese equivalents. Japanese kana (Hiragana U+3040-U+309F, Katakana U+30A0-U+30FF) frequently corrupt to U+FFFD (�) when code passes through LLM output, heredoc, or terminal encoding layers.
   199→   199→> Common safe replacements: `活の真鲷`→`活缔真鲷`, `盐烤の鲭鱼`→`盐烤鲭鱼`, `烤の鸡串`→`炭烤鸡串`.
   200→   200→> If the character is genuinely needed, verify it survives a full write→read round-trip with `open(file, encoding='utf-8')`.

   205→   205→
   206→   206→### CRITICAL: Allowed Fonts Only
   207→   207→**You MUST ONLY use the following registered fonts. Using ANY other font is STRICTLY FORBIDDEN.**
   208→   208→
   209→   209→| Font Name | Usage | Path |
   210→   210→|-----------|-------|------|

   212→   212→| `SimHei` | Chinese body text | `/usr/share/fonts/truetype/chinese/SimHei.ttf` |
   213→   213→| `SarasaMonoSC` | Chinese code blocks | `/usr/share/fonts/truetype/chinese/SarasaMonoSC-Regular.ttf` |
   214→   214→| `Times New Roman` | English text, numbers, tables | `/usr/share/fonts/truetype/english/Times-New-Roman.ttf` |

   236→   236→pdfmetrics.registerFont(TTFont('Times New Roman', '/usr/share/fonts/truetype/english/Times-New-Roman.ttf'))
   237→   237→pdfmetrics.registerFont(TTFont('Calibri', '/usr/share/fonts/truetype/english/calibri-regular.ttf'))

   240→   240→pdfmetrics.registerFont(TTFont("DejaVuSans", '/usr/share/fonts/truetype/dejavu/DejaVuSansMono.ttf'))

   242→   242→# CRITICAL: Register font families to enable <b>, <super>, <sub> tags

   250→   250→### Font Configuration by Document Type
   251→   251→
   252→   252→**For Chinese PDFs:**
   253→   253→- Body text: `SimHei` or `Microsoft YaHei`
   254→   254→- Headings: `Microsoft YaHei` (MUST use for Chinese headings)
   255→   255→- Code blocks: `SarasaMonoSC`
   256→   256→- Formulas/symbols: `DejaVuSans`
   257→   257→- **In tables: ALL Chinese content and numbers MUST use `SimHei`**
   258→   258→
   259→   259→**For English PDFs:**
   260→   260→- Body text: `Times New Roman`
   261→   261→- Headings: `Times New Roman` (MUST use for English headings)
   262→   262→- Code blocks: `DejaVuSans`
   263→   263→- **In tables: ALL English content and numbers MUST use `Times New Roman`**
   264→   264→
   265→   265→**For Mixed Chinese-English PDFs:**
   266→   266→- Call `install_font_fallback()` once after registering fonts - it automatically wraps characters in `<font>` tags so you don't need to do it manually.
   267→   267→- If you still want manual control, you can use `<font name='...'>` tags, but the automatic fallback handles most cases.
   268→   268→
   269→   269→```python
   270→   270→import sys, os
   271→   271→sys.path.insert(0, os.path.join(os.path.dirname(__file__), 'scripts'))
   272→   272→from pdf import install_font_fallback
   273→   273→
   274→   274→# 1. Register fonts (as above)
   275→   275→# 2. Install fallback - one line, handles all mixed-language text
   276→   276→install_font_fallback()
   277→   277→
   278→   278→# 3. Just write naturally - no manual <font> wrapping needed!
   279→   279→en_style = ParagraphStyle(name="EN", fontName="Times New Roman", fontSize=10.5, leading=18)
   280→   280→cn_style = ParagraphStyle(name="CN", fontName="SimHei", fontSize=10.5, leading=18)
   281→   281→
   282→   282→Paragraph('MySQL、PostgreSQL、Redis', en_style)           # ✅ CJK comma auto-fallback to SimHei
   283→   283→Paragraph('Beijing (北京) has 21M people', en_style)       # ✅ CJK chars auto-fallback
   284→   284→Paragraph('价格:¥2,200~5,800/月', en_style)               # ✅ all CJK chars handled
   285→   285→Paragraph('《巴黎协定》签署于2015年', en_style)               # ✅ CJK book title marks handled
   286→   286→```
   287→   287→
   288→   288→**How it works:** `install_font_fallback()` monkey-patches `Paragraph.__init__` to scan each character against the font's `charToGlyph` table. Characters missing from the base font are automatically wrapped in `<font name="FallbackFont">`. The fallback chain is: English fonts → SimHei, Chinese fonts → Times New Roman. For aesthetic optimization, Cyrillic text in SimHei is automatically routed to Times New Roman (serif looks better for Cyrillic).

   305→   305→## Layout & Spacing Control
   306→   306→
   307→   307→### Page Breaks
   308→   308→
   309→   309→Follow the document type strategy defined in SOUL.md Rule 1.
   310→   310→
   311→   311→**Structural breaks (always - MANDATORY):**
   312→   312→- Between cover page and TOC - **cover must NEVER share a page with anything else**
   313→   313→- Between TOC and main content
   314→   314→- Between main content and back cover
   315→   315→
   316→   316→**Content breaks (by document type):**
   317→   317→- **Default (all document types)**: ❗ **Absolutely NEVER force page breaks before H1/H2** — content flows naturally, do not insert `PageBreak()` before section headings. This is an iron rule.
   318→   318→- Resume / contract / letter → No content page breaks
   319→   319→- Short article → No content page breaks
   320→   320→- **Exception 1**: Academic papers / textbooks / teaching plans → `PageBreak()` before each H1 is acceptable (only if user explicitly requests academic formatting)
   321→   321→- **Exception 2**: User explicitly requests page breaks between chapters
   322→   322→
   323→   323→**Anti-tear (mandatory — but with height limit):**
   324→   324→```python
   325→   325→from reportlab.platypus import KeepTogether
   326→   326→from reportlab.lib.pagesizes import A4
   327→   327→from reportlab.lib.units import inch
   328→   328→
   329→   329→# Maximum height for KeepTogether blocks: 40% of page height
   330→   330→# Blocks taller than this should NOT be kept together — they cause
   331→   331→# the preceding page to be mostly empty when the block gets pushed down.
   332→   332→MAX_KEEP_HEIGHT = A4[1] * 0.4  # ~336pt ≈ 12cm
   333→   333→
   334→   334→def safe_keep_together(elements):
   335→   335→    """Wrap elements in KeepTogether only if their total height is reasonable.
   336→   336→    If too tall, keep only the FIRST TWO elements together (e.g. title + table/image header)
   337→   337→    to prevent title-content separation, while letting the rest paginate naturally.
   338→   338→    """
   339→   339→    total_h = 0
   340→   340→    for el in elements:
   341→   341→        w, h = el.wrap(A4[0] - 2*inch, A4[1])
   342→   342→        total_h += h
   343→   343→    if total_h <= MAX_KEEP_HEIGHT:
   344→   344→        return [KeepTogether(elements)]
   345→   345→    elif len(elements) >= 2:
   346→   346→        # Keep at least title + first element together to prevent title orphaning
   347→   347→        return [KeepTogether(elements[:2])] + list(elements[2:])
   348→   348→    else:
   349→   349→        return list(elements)
   350→   350→
   351→   351→# Heading stays with first paragraph
   352→   352→story.extend(safe_keep_together([
   353→   353→    heading_paragraph,
   354→   354→    first_body_paragraph,
   355→   355→]))
   356→   356→
   357→   357→# Image + caption: keep together ONLY if image is small
   358→   358→story.extend(safe_keep_together([image, caption_paragraph]))
   359→   359→
   360→   360→# Table title + table: keep together ONLY if table is short
   361→   361→if len(table_data) <= 15:
   362→   362→    story.extend(safe_keep_together([table_title, table]))
   363→   363→else:
   364→   364→    # Long table: just keep title with the table start
   365→   365→    story.extend(safe_keep_together([table_title]))
   366→   366→    story.append(table)
   367→   367→```
   368→   368→
   369→   369→**⚠️ KEY INSIGHT:** `KeepTogether` is the #1 cause of “empty page with chart on next page”.
   370→   370→When a `KeepTogether` block is taller than the remaining space on the current page,
   371→   371→ReportLab pushes the **entire block** to the next page, leaving the current page mostly empty.
   372→   372→**Always use `safe_keep_together()` to cap the maximum block height.**
   373→   373→
   374→   374→**⚠️ Note:** Do NOT use `KeepWithNext` - it is unreliable in ReportLab 4.x.
   375→   375→
   376→   376→### Vertical Spacing Standards
   377→   377→* Before tables: `Spacer(1, 18)` after preceding text
   378→   378→* After tables: `Spacer(1, 6)` before table caption
   379→   379→* After table captions: `Spacer(1, 18)` before next content
   380→   380→* Between paragraphs: `Spacer(1, 12)` (~1 line)
   381→   381→* Between H3 subsections: `Spacer(1, 12)`
   382→   382→* Between H2 sections: `Spacer(1, 18)` (~1.5 lines)
   383→   383→* Between H1 sections: `Spacer(1, 24)` (~2 lines)

   386→   386→### Cover Page: HTML/Playwright Unified Cover System
   387→   387→
   388→   388→**⚠️ Report route covers are ALWAYS generated via HTML/Playwright**, using the same 7-template system defined in `typesetting/cover.md`. This ensures visual consistency across all routes (Report, Creative, Academic) and avoids the limitations of ReportLab for complex cover layouts.
   389→   389→

   391→   391→1. Generate **body PDF** via ReportLab (start with TOC or content - **no cover in story[]**)

   468→   468→
   469→   469→**Insertion script (single output PDF):**
   470→   470→```python
   471→   471→from pypdf import PdfReader, PdfWriter, Transformation
   472→   472→
   473→   473→A4_W, A4_H = 595.28, 841.89  # A4 in points
   474→   474→
   475→   475→def normalize_page_to_a4(page):
   476→   476→    """Scale a page to A4 if its dimensions don't match."""
   477→   477→    box = page.mediabox
   478→   478→    w, h = float(box.width), float(box.height)
   479→   479→    if abs(w - A4_W) > 2 or abs(h - A4_H) > 2:
   480→   480→        sx, sy = A4_W / w, A4_H / h
   481→   481→        page.add_transformation(Transformation().scale(sx=sx, sy=sy))
   482→   482→        page.mediabox.lower_left = (0, 0)
   483→   483→        page.mediabox.upper_right = (A4_W, A4_H)
   484→   484→    return page
   485→   485→
   486→   486→def insert_cover(cover_pdf, body_pdf, output_pdf):
   487→   487→    """Insert cover as first page of body PDF → single output file."""
   488→   488→    writer = PdfWriter()
   489→   489→    # Cover as page 1
   490→   490→    cover_page = PdfReader(cover_pdf).pages[0]
   491→   491→    writer.add_page(normalize_page_to_a4(cover_page))
   492→   492→    # Body pages follow
   493→   493→    for page in PdfReader(body_pdf).pages:
   494→   494→        writer.add_page(normalize_page_to_a4(page))
   495→   495→    writer.add_metadata({'/Title': 'Report Title', '/Author': 'Z.ai', '/Creator': 'Z.ai'})
   496→   496→    with open(output_pdf, 'wb') as f:
   497→   497→        writer.write(f)
   498→   498→```
   499→   499→
   500→   500→> **⚠️ Size pitfall:** Playwright `page.pdf(width='794px', height='1123px')` output PDF dimensions may differ from A4 (595.28×841.89pt) by 1-2pt. **Do not use PIL Image.save('x.pdf')** for PNG→PDF conversion — DPI mapping causes severe size errors. You must call `normalize_page_to_a4()` to unify dimensions before insertion.
